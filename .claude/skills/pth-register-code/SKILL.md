# pth-register-code (SK-09)

Записывает связь «коммит реализует требование». Важно: это утверждение автора, а не доказательство реализации. Статус проверки в PTH вычисляется отдельно.

## Вход

- Ключ проекта, полный или короткий SHA коммита (7–40 hex-символов), заголовок коммита.
- ID требований, которые коммит реализует (`PTH-FR-012`), минимум один.
- `PTH_URL` и `PTH_TOKEN` с правом записи в проект.

## Шаги

1. Проверь доступ: `sdk/pth me`. Нужна роль writer для этого проекта.
2. Проверь каждый ID: `sdk/pth artifact <KEY> <ID>`. Если элемента нет, остановись и сообщи.
3. Проверь, что SHA корректен и не зарегистрирован. Повтор вернёт 409 `COMMIT_EXISTS` — это нормально, сообщи пользователю.
4. Покажи пользователю, что будет записано: SHA, заголовок, список требований. Спроси подтверждение.
5. После «да» запиши: `sdk/pth commit <KEY> <SHA> "<заголовок>" --implements <ID> [<ID> ...]`.
6. Проверь: `sdk/pth context <KEY> <ID>` — требование больше не должно попадать в список `no_code_link` по этому коммиту.

## Выход

Зарегистрированный коммит (`display_id`, SHA) и список связанных требований. Укажи, что статус проверки («проверено» или «реализовано») не выставлен этим действием.

## Границы

- Не придумывай SHA и не бери его из сообщений коммитов без проверки пользователем.
- Не регистрируй коммит без подтверждения.
- Наличие ID в заголовке коммита не доказывает реализацию. Не говори «требование выполнено».
- Не удаляй и не меняй существующие связи: в скилле этих операций нет.
