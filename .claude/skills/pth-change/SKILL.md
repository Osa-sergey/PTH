# pth-change (SK-03)

Все правки PTH идут через черновик ChangeSet. Сначала показываем, что изменится, затем применяем только с подтверждением. Если кто-то изменил требование раньше, сервер отклонит правку (409), и мы не перезапишем чужую работу.

## Вход

- Ключ проекта, ID требования (`PTH-FR-012`), новая формулировка или связь, которую надо добавить.
- `PTH_URL` и `PTH_TOKEN` с правом записи в проект. Без него остановись и попроси пользователя задать токен.

## Шаги

1. Прочитай текущее состояние: `sdk/pth artifact <KEY> <ID>`. Запомни `revision`.
2. Сформируй JSON-файл черновика. Для новой ревизии:
   ```json
   {"title": "Правка PTH-FR-012", "operations": [
     {"op": "add_revision", "display_id": "PTH-FR-012", "title": "новое название",
      "text": "новый текст", "attributes": {"priority": "P0"}}]}
   ```
   Для связи:
   ```json
   {"title": "Связь", "operations": [
     {"op": "create_relation", "type": "refines", "source": "PTH-FR-012", "target": "PTH-US-004"}]}
   ```
   Номер ревизии (`expected_revision`) не задаётся: сервер ставит текущую ревизию сам при создании черновика. Если элемент изменили после этого, применение вернёт 409.
3. Создай черновик: `sdk/pth propose <KEY> <файл.json>`. Покажи пользователю `uid`, список операций и различие со старой ревизией: старое название и текст против нового.
4. Спроси подтверждение. Без явного «да» ничего не применяй.
5. Примени: `sdk/pth apply-changeset <KEY> <uid>`.
6. Проверь результат: `sdk/pth artifact <KEY> <ID>`. Номер ревизии должен вырасти на единицу.

## Выход

- `uid` черновика и список операций до применения.
- Результат: применено или не применено, новая ревизия.

## Границы

- Не применяй без подтверждения пользователя в этом же разговоре.
- Не меняй ID, не создавай артефакты и не удаляй связи: этих операций в скилле нет.
- Если `apply-changeset` вернул 409 `REVISION_CONFLICT`, сообщи, что требование изменили раньше. Прочитай его заново, покажи пользователю разницу и предложи повторить с актуальной ревизией. Не отправляй правку с новым `expected_revision` без подтверждения.
- Если применение упало с другой ошибкой, данные не изменены, черновик остаётся. Покажи `last_error`.
- Не придумывай атрибуты и приоритет, которых пользователь не называл.
