# pth-import-spec (SK-01)

Загружает спецификацию в проект PTH так, чтобы пользователь видел все изменения до записи.

## Вход

- Ключ проекта PTH (например `PTH`) и путь к файлу спеки.
- Переменные окружения: `PTH_URL` (по умолчанию `http://127.0.0.1:8000`) и `PTH_TOKEN` (ключ с правом записи в проект).

Если `PTH_TOKEN` не задан, остановись и попроси пользователя задать его. Не ищи токены в других местах и не выпускай новые ключи без просьбы.

## Шаги

1. Проверь доступ: `sdk/pth projects`. Ошибка 401 или 403 — сообщи пользователю код и текст, не обходи.
2. Прочитай файл целиком. Не импортируй фрагмент и не сокращай текст.
3. Предпросмотр без записи:
   `sdk/pth import <KEY> <файл> --dry-run`
4. Покажи пользователю сводку: создано, изменено, без изменений, связей, нераспознано, и список `changes` по ID.
5. Если `unparsed` не пуст, перечисли строки и спроси, исправлять ли файл. Не импортируй их молча.
6. Спроси подтверждение. Записывай через черновик, а не напрямую:
   `sdk/pth import <KEY> <файл> --changeset`
   Выведи `changeset_uid`.
7. Примени черновик только после явного «да» пользователя:
   `sdk/pth apply-changeset <KEY> <uid>`
8. Проверь результат: `sdk/pth lost <KEY> --type US` и сообщи число потерянных user story.

## Выход

- Сводка предпросмотра, uid черновика, результат применения, число элементов и связей в проекте.
- Список нераспознанных строк, если есть.

## Границы

- Прямой импорт без черновика в этом скилле не используется.
- Не выделяй требования моделью: это отдельная процедура и только по просьбе пользователя.
- Не придумывай ID, названия и связи, которых нет в файле.
- Таблицы DEC, SK и ADR импортом не обрабатываются, это ожидаемое поведение.
- Если применение черновика вернуло ошибку, данные не изменены, черновик остаётся. Покажи `last_error` и предложи исправить файл.
