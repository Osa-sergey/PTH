# pth-project-answer (SK-12)

Отвечает на вопрос по данным PTH и показывает, откуда ответ. Каждое утверждение опирается на ID и номер ревизии. Только читает данные.

## Вход

- Ключ проекта и вопрос на русском или английском.
- `PTH_URL` и `PTH_TOKEN` с правом чтения.

## Шаги

1. Проверь доступ: `sdk/pth me`.
2. Найди кандидатов по тексту: `sdk/pth search <KEY> "<ключевые слова>"`. Если вопрос про тип элемента, добавь `--type FR` или другой тип. Попробуй 2–3 формулировки из вопроса, если первая дала мало.
3. Для 3–5 самых релевантных ID собери контекст: `sdk/pth context <KEY> <ID> --depth 1`. Возьми текст, ревизию, исключение (`excluded`) и связи.
4. Если в ответе есть решение (ADR) или требование с исключением, проверь, не замещено ли оно: посмотри связи и ревизии.
5. Если вопрос про статус выполнения, добавь `lost` и `status`: `sdk/pth status <KEY>`.

## Выход

Ответ на русском в 3–10 предложениях. После ответа — список источников: ID, ревизия, короткая цитата из текста. Если данных не хватает, так и скажи и предложи, что уточнить.

## Границы

- Только чтение. Не создавай и не меняй элементы.
- Отвечай только по данным PTH. Если найденного недостаточно, скажи «в PTH не найдено» и не дополняй из памяти или общих знаний.
- Не выдавай устаревшее решение за действующее. Если ревизия или связь указывает на замену, скажи об этом явно.
- Не утверждай, что функция реализована, по наличию требования: статус реализации в PTH отдельный (см. `status` и `lost`).
- Если поиск ничего не дал, попробуй синонимы один раз, затем честно скажи, что не найдено.
