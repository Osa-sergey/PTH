# Статус реализации

> Вручную ведётся по факту. Статусы: **реализовано** — есть в коде и покрыто проверкой; **частично** — есть срез, перечислено, чего нет; **не начато**. «Проверено вручную» — прогон в браузере, не автоматический тест.

Охват: срез E1 (API), минимальный импорт E2 и UI для US-055/056. Остальные US, ФТ и AC спеки не начаты.

## Импорт принятой спецификации (этап E2, минимальный срез)

Реализовано: `POST /v1/projects/{key}/imports` разбирает таблицы с колонкой `ID` (US/FR/NFR/AC), создаёт артефакты с внешним ключом = ID документа, связи `refines` FR/NFR/AC → US из колонки «Основание», журнал `ImportSession` с исходным текстом и SHA-256. Повтор того же текста не создаёт дублей; изменившаяся строка получает новую ревизию. Таблицы решений (DEC), скиллов (SK) и ADR пропускаются как вне области. Реальный файл спеки: 196 элементов, 196 связей, 0 нераспознанных строк (`server/tests/test_api.py::test_import_of_repository_spec_matches_registry`).

Истории Storybook: `Import.stories.tsx`. Проверено в браузере: предпросмотр не создаёт элементы (404 по ID после предпросмотра), связь с элементами предыдущего импорта создаётся (исправлен дефект: раньше цели искались только в текущем файле).

Добавлено: импорт строит план операций. `?as_changeset=true` сохраняет план черновиком ChangeSet, данные не меняются; `POST /changesets/{uid}/apply` применяет все операции в одной транзакции. Ошибка откатывает все операции, черновик остаётся, причина видна в `last_error`. Повторное применение — 409. Проверено в браузере: черновик создан (PTH-FR-903 не записан, 404), после «Применить» элемент появился и связан с PTH-US-001, в журнале появилась запись.

Статус FR-012 после этого: **частично** — импорт через черновик есть, но прямой импорт (`apply`) по-прежнему пишет сразу, и правки вне импорта (UI, API) через ChangeSet не проходят.

Известные ограничения импорта:

- Диапазоны ID вида `PTH-US-002–005` не раскрываются: связи на эти US не создаются.
- Прямой импорт (без черновика) пишет в канонические данные сразу.
- Строки, где ID не в первой колонке таблицы, не извлекаются.

## Доступ и проекты (минимальный срез)

Реализовано: API-ключи (в БД только SHA-256), роли admin / writer / reader, ограничение по проекту. Без токена — 401, чужой проект или недостаточная роль — 403. Создавать проекты может только admin. Тесты: `test_requests_without_token_get_401`, `test_reader_can_read_but_not_write`, `test_writer_is_isolated_to_its_project`, `test_revoked_key_stops_working`, `test_tokens_are_stored_only_as_hashes`.

Выпуск ключа: `PYTHONPATH=. .venv/bin/python scripts/create_key.py admin "имя"` или `... project КЛЮЧ "имя" writer`. Токен показывается один раз.

Проекты в UI: селектор проектов, кнопка «Новый проект» с пояснением, после создания — переход к импорту. Импорт в проект даёт собственные ID (`SHOP-FR-001`); исходный ID документа хранится как внешний ключ (`external_key`), по спеке §1.5.

Статусы: FR-070 — **частично** (ключи и проект, без пользователей, сессий и ролей внутри проекта сверх трёх уровней); FR-071 — **частично** (выпуск и отзыв есть, журнала использования и scopes нет). NFR-019 — проверено тестами изоляции по записи и чтению.

Ограничения: отзыв ключа — только через `revoke` в коде, CLI пока нет; удаления проектов нет; название проекта при импорте = ключ, его нельзя изменить через API.

## Разбор всей спеки по частям (фон)

Реализовано: `POST /v1/projects/{key}/extractions/jobs` делит документ по заголовкам и абзацам (фрагменты до 3000 символов), прогоняет каждый через модель и хранит прогресс в БД после каждого фрагмента. `GET .../jobs/{uid}` отдаёт состояние, прогресс и найденное. Одинаковые названия из разных фрагментов схлопываются. Недоступность модели останавливает задачу с состоянием `failed`, найденное сохраняется. Задача ничего не пишет в проект: результат идёт в черновик. UI: кнопка «Весь документ по частям» с полосой прогресса в разделе «Импорт».

Проверено: 3 теста (разбиение, сбор с дедупликацией и прогрессом, остановка при недоступной модели). **Полный прогон на спецификации идёт**: 121 фрагмент, примерно 20 секунд на фрагмент. Качество выделения на всём документе не оценено.

Ограничения: задача в памяти процесса; после перезапуска API она не возобновляется (состояние в БД остаётся, продолжить нельзя). Отмены задачи нет.

## Git и CI: прогоны тестов на коммите (одиннадцатый шаг)

## Схемы процессов (DIAGRAM)

- **Тип артефакта DIAGRAM** (`PTH-DIAGRAM-001`): исходник лежит в тексте ревизии, формат — атрибут `format`: `mermaid` или `svg`. Новая связь `illustrates` от схемы к процессу — US или ФТ (к AC, НФТ и прочим нельзя). Схема привязана к нескольким процессам и наоборот.
- **Проверки:** формат обязателен, текст не пустой и до 1 МБ. SVG разбирается как XML, корень `svg`, без `<script>`, `on*`-обработчиков, `javascript:`, DOCTYPE и сущностей. Проверки идут и при создании, и при новой ревизии.
- **Показ:** Mermaid рисуется библиотекой `mermaid` в строгом режиме (подгружается по требованию), SVG выводится как изображение, поэтому скрипты внутри не исполняются. Вкладка «Схемы»: список, создание с живым просмотром и загрузкой файла, карточка с привязкой к процессам. Карточка US или ФТ показывает «Схемы процесса».
- **Замечания и влияние:** правило `DIAGRAM_NOT_LINKED`; правила `IMP-ILLUSTRATED-BY` (изменился процесс — актуализировать схему) и `IMP-ILLUSTRATES` (изменилась схема — сверить описание).
- Тест: `test_diagram_artifact_formats_validation_links_review_and_impact`.
- **Не сделано:** векторные форматы кроме SVG (PDF, EPS, drawio), хранение SVG и больших файлов как вложений, сравнение ревизий схемы визуально, выбор схемы на карте историй и в релизе (в состав релиза берутся только US, ФТ, НФТ, AC).

## Источник и трассировка к первоисточнику

- **Вкладка «Источник»:** документ импорта показывается в двух видах: «Документ» (Markdown-рендер) и «Исходник» (строки с номерами). Подсвечены формулировки, из которых получены требования: строка таблицы или абзац слева с акцентной полосой. Нажатие на подсвеченное открывает карточку требования. Справа список «Требования в источнике» с переходом к строке. Открывается самый свежий импорт.
- **От требования к источнику:** в карточке US, ФТ, НФТ, AC и других элементов блок «Первоисточник» (`GET /artifacts/{id}/origins`): документ, строка, текст формулировки и кнопка «Открыть в источнике», которая открывает документ на этой строке. У элемента, созданного вручную, пишется, что источника нет.
- **Старые импорты:** привязка строк хранилась не у всех импортов. Если её нет, она восстанавливается из сохранённого текста источника разбором таблиц и сопоставлением по внешнему ID (проверено на импорте спеки PTH).
- **Ячейки таблицы:** строка подсвечивается, а ячейки с формулировкой (название, у US ещё и цель) выделены сильнее. Индексы ячеек сохраняются в привязке (`cols`).
- **Цитаты модели:** черновик из предложений модели (`POST /extractions/changesets`) принимает `source` (имя и текст). Цитата ищется в тексте (пробелы и переносы нестрого), строки и колонки сохраняются, а источник записывается как импорт при применении черновика. В документе подсвечивается абзац пунктирной полосой, в «Исходнике» точно процитированное место; недословная цитата подсвечена жёлтым. Предложения, которые модель дала без исходного текста, подсветки не имеют, как и цитаты, которых в тексте нет.
- **Сравнение версий источника:** `GET /sources/compare?a=&b=`, вкладка «Источник → Сравнение версий»: построчный diff в видах «Вместе» и «Рядом», сводка (+добавлено, −убрано) и требования, чьи формулировки изменились, появились или пропали.
- **Не сделано:** подсветка внутри ячейки по точной цитате (подсвечивается весь абзац или ячейка), сравнение источников разных документов по смыслу (сравнение построчное), привязка предложений, созданных фоновой задачей без исходного текста в черновике.

## Граф по уровням от центра

- **Глубина:** выбор «Уровней от центра» от 1 до 6 (сервер принимает `depth` до 6, раньше до 3). У каждого узла в ответе поле `level` — расстояние от центра в связях. Подписи «ур. N» на узлах и сводка «по уровням: 0: 1, 1: 3, 2: 17».
- **Раскладка:** «По связям» (слои Dagre, как раньше) и «По уровням от центра»: центр посередине, каждый уровень на своей окружности, потомки стоят в стороне своего родителя. Рёбра прямые, от края узла к краю; полотно выше (760 px). Тесты раскладки: `layout.test.ts`; сервер: `test_graph_nodes_carry_level_and_depth_goes_up_to_six`.
- **Свёртка уровней:** «Свернуть с уровня N» заменяет уровень одним счётчиком («▸ Уровень 2: 17, и глубже ещё 18»), всё глубже скрыто; рёбра сходятся на счётчике. Нажатие на счётчик раскрывает один уровень. Проверено на PTH-FR-009: 73 узла при 4 уровнях сворачиваются до 5.
- **Подсветка цепочки:** выбранный узел подсвечивает кратчайшую цепочку связей от центра до него (узлы акцентной рамкой, рёбра толще), остальное приглушено; флажок «Подсвечивать цепочку до выбранного». Тесты: `collapse.test.ts`.
- **Не сделано:** окружности-направляющие на фоне, перенос глубины, раскладки и свёртки в адрес, свёртка отдельной ветки (сворачивается уровень целиком).

## Импорт: мастер, предпросмотр и правка

- **Вкладка «Импорт»:** «Новый импорт», «Черновики», «Журнал». Новый импорт идёт в два шага: источник и проверка. Способ выбирается явно: «Таблицы Markdown» или «Выделить моделью», справа объяснение, как из текста получаются сущности, и пример (для таблиц кнопка «Вставить пример»).
- **Таблицы:** `POST /imports/preview` ничего не пишет и возвращает элементы (создаётся, новая ревизия, без изменений), связи из столбца «Основание» и неразобранные строки. Теперь принимается любой префикс ID документа (`SHOP-FR-12`, `PTH-FR-001`), раньше только `PTH-`.
- **Модель:** быстрое выделение из фрагмента или обработка всего документа по частям с прогрессом; предложения попадают в тот же предпросмотр. К каждому предложению цитата из текста.
- **Предпросмотр и правка:** карточка на элемент (включить, тип, название, формулировка, приоритет), правка связей с поиском цели по названию или ID среди элементов черновика и проекта (допустимые типы концов проверяются), фильтры «Новые, Новые ревизии, Без изменений, С проблемами». Справа исходный текст: «Документ» и «Исходник», подсвечены строки таблиц и ячейки с формулировкой; цитаты модели подсвечены в самом тексте. Нажатие на подсвеченное выбирает элемент. Цитату можно заменить, выделив фразу в тексте.
- **Создание:** `POST /drafts` собирает черновик из отредактированных элементов и связей, проверяет допустимость связей сразу, сохраняет источник с привязкой фрагментов. Кнопки «Создать черновик» и «Создать и применить».
- Тест: `test_import_preview_and_edited_draft_with_links_and_source`, `test_import_accepts_any_document_prefix_in_ids`.
- **Не сделано:** правка отдельных связей типа motivates на ADR вне проекта, предупреждение о занятом ID до применения (при совпадении номера применение вернёт 409), редактирование нескольких цитат на один элемент, привязка выделения в режиме «Документ» (работает в «Исходнике»).


## Изменения (ChangeSet): просмотр и механизм

- Раздел «Данные → Изменения»: список (фильтр «все / черновики / применённые», пагинация), блок «Как работают изменения», карточка изменения с вкладками «Операции», «Источник» (подсветка фрагментов, если у черновика есть источник) и «JSON» (правка операций черновика).
- Операции показываются человеческим языком: создание элемента, новая ревизия с пословной разницей (у применённого изменения сравнение с ревизией, от которой оно сделано), связь или удаление связи с названиями концов.
- У черновика есть проверка применения: сервер выполняет операции вхолостую и откатывает (`GET /v1/projects/{key}/changesets/{uid}/review`); видно, на какой операции применение упадёт. Кнопки «Применить», «Проверить заново», «Отклонить» (`DELETE`, только черновики).
- Вкладка «Черновики» из импорта удалена: черновики смотрятся только в разделе «Изменения».
- Проверено: pytest сервера (92), tsc, vite build, vitest (13); вручную в браузере на проекте PTH открыты применённое изменение и демо-черновик (проверка, операции, разница). Кнопки «Применить» и «Отклонить» в браузере не нажимались (отклонение проверено через API и тест сервера). Вкладка «Источник» проверена только на уровне типов.
